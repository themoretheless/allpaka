# allpaka Studio

Веб-чат внутри allpaka, запускается отдельно от inference и не требует загрузки GGUF:

```bash
cargo build -p allpaka-cli --no-default-features
./target/debug/allpaka studio --workspace /absolute/path/to/project
```

Открыть адрес, напечатанный сервером: по умолчанию `http://127.0.0.1:8100`.
`--bind` принимает только loopback. `--data-dir` переопределяет каталог истории;
по умолчанию это `$HOME/.allpaka/studio` (на Windows — `USERPROFILE`).
Это однопользовательский локальный сервис, не публичный веб-сервер.
Существующие `allpaka serve` и CLI-команда `allpaka chat` сохранены.

## Провайдеры

| Подключение | Переменная окружения | Протокол |
|---|---|---|
| OpenAI / модели ChatGPT | `OPENAI_API_KEY` | Chat Completions |
| Claude | `ANTHROPIC_API_KEY` | Native Messages |
| DeepSeek | `DEEPSEEK_API_KEY` | Chat Completions |
| Kimi | `MOONSHOT_API_KEY` | Chat Completions |
| Grok | `XAI_API_KEY` | Chat Completions |
| Gemini | `GEMINI_API_KEY` | OpenAI-compatible Chat Completions |
| OpenRouter | `OPENROUTER_API_KEY` | Chat Completions |
| allpaka local | необязательный `ALLPAKA_LOCAL_API_KEY` | Chat Completions |

Ключ можно ввести в «Подключениях» и выбрать память процесса или системное
хранилище (подробнее ниже). Он не попадает в историю, экспорт или браузерное
хранилище. Ключ только в памяти требуется ввести заново после перезапуска. Список моделей загружается кнопкой «Обновить
список», Model ID можно ввести вручную. Подписка на веб-чат не заменяет API-ключ.
Для локального сервера используется `http://127.0.0.1:8099/v1`;
`ALLPAKA_LOCAL_BASE_URL` позволяет указать другой локальный совместимый сервер.
Перенаправления HTTP отключены. Удалённые провайдеры используют HTTPS.

Адаптеры не обещают поддержку всех функций каждой модели. Выбирайте модель с
function calling для работы с папками/Auto и vision для изображений. Подключение
DeepSeek в этой версии текстовое; запрос с изображениями отклоняется явно.
Ошибки HTTP, неполные потоки и некорректные аргументы инструментов не выдаются
за успешный ответ. Reasoning и Gemini tool signatures сохраняются для повторных
запросов к тому же провайдеру; чужие служебные поля не передаются при переключении.
Возможности OpenAI Responses, native Gemini, provider-side web search, extended
thinking Claude и live mid-turn steering пока не подключены.

Первичные спецификации:
[OpenAI streaming](https://developers.openai.com/api/docs/guides/streaming-responses),
[Claude Messages](https://platform.claude.com/docs/en/api/messages),
[DeepSeek](https://api-docs.deepseek.com/),
[Kimi](https://platform.kimi.ai/docs/overview),
[xAI](https://docs.x.ai/developers/rest-api-reference),
[Gemini compatibility](https://ai.google.dev/gemini-api/docs/openai).

## Проекты и контекст

Проект содержит имя, инструкции и до 20 локальных папок или уже клонированных
репозиториев. У каждой папки — уникальное имя контекста и отдельное разрешение
записи. Репозиторий определяется по наличию `.git`; клонирование URL пока не
выполняется. Чат привязан к одному проекту. Смена проекта открывает новый чат,
старые разговоры остаются в исходном проекте.

Пример подключения:

- `app` → `/work/app` — рабочий репозиторий;
- `backend` → `/work/service` — второй репозиторий;
- `reference` → `/work/docs` — справочные материалы только для чтения.

Модель использует `list_files(".")`, `list_files("app/src")` и
`read_file("reference/spec.md")`. Содержимое папок не отправляется целиком:
инструменты читают нужные файлы по мере выполнения. Внешнему API передаются
сообщения, инструкции, вложения и прочитанный контекст. Пути на диске, скрытые
папки и хранилище разговоров не становятся доступными автоматически.
`read_file` принимает `start_line`/`end_line` (включительно, с 1): файл до 8 MiB, выдача до 128 KiB. Возвращает границы и общее число строк. Листинг ограничен 200 записями.
Симлинки, абсолютные пути инструментов и выход через `..` отклоняются.
Это ограничения приложения для локальной работы, а не ОС-песочница против
одновременно изменяющего файловую систему процесса.

«Файл», вставка из буфера и drag-and-drop добавляют текст/код или PNG, JPEG,
WebP, GIF к сообщению. До четырёх изображений, суммарно до 6 MB; они сохраняются
в истории и отправляются как изображения API. Локальный движок allpaka картинки
пока не принимает: без vision-проектора `/v1/chat/completions` отвечает явной
ошибкой `images_unsupported` (HTTP 400), а не тихим пустым ответом. Облачные
провайдеры с vision и `ALLPAKA_LOCAL_BASE_URL`, указывающий на внешний
OpenAI-совместимый vision-сервер, работают как раньше. Текстовые вложения ограничены
100 KB на файл и общим лимитом сообщения. Вложенный текст — данные, а не новые
системные инструкции. PDF, DOCX, XLSX, OCR, аудио, видео и архивы пока не
извлекаются. Для больших репозиториев следующим этапом нужен поиск/RAG.

## Режимы и управление

| Действие | Контракт |
|---|---|
| Chat | Ответы и инструменты чтения подключённого контекста. Без записи. |
| Plan | Исследование и план (`set_plan`). Запись запрещена сервером независимо от ответа модели. |
| Auto | Цикл инструментов до ответа или лимита шагов. Запись доступна только при разрешении в чате и у конкретной папки. |
| Goal | Цель вместо шага: сначала план с критериями готовности, затем исполнение, проверка и обновление плана. Запись — как в Auto. |
| Swarm | Волна независимых агентов по одной задаче и один сводный MASTER-ответ. Только чтение контекста. |
| Отправить во время работы | Добавить сообщение в FIFO-очередь со снимком выбранной модели/режима. |
| Steer | Уточнить текущую задачу на ближайшей границе шага; не прерывает текущий поток. Неисполненный остаток пакета tool calls отменяется и переоценивается. |
| Send now | Отменить активный HTTP-запрос и сразу начать новое сообщение. Частичный текст и обычная очередь сохраняются. |
| Stop | Прервать выполнение и приостановить очередь. |
| Продолжить | Выполнить сохранённую очередь либо продолжить задачу явным сообщением. |

Отмена не откатывает уже завершённую запись и не гарантирует прекращение
биллинга удалённого сервера. На границах инструментов сохраняются результаты,
незавершённым вызовам добавляется результат отмены, чтобы история API оставалась
корректной. Лимит — 1–50 запросов модели на задачу, по умолчанию 12. Лимит ответа
настраивается в интерфейсе: по умолчанию 8192 выходных токена на запрос,
диапазон 256–131072; выбранная модель может иметь меньший максимум. При
`length` / `max_tokens` задача штатно приостанавливается: текст, reasoning и
usage сохраняются, а оборванные вызовы инструментов не исполняются и не
передаются провайдеру как завершённые. Увеличьте лимит и нажмите «Продолжить»:
продолжение незаконченного ответа выполняется перед сохранённой очередью. Очередь — до 32 обычных сообщений,
Steer — до 32 уточнений. При ошибке очередь приостанавливается, чтобы не терять
последующие сообщения и не повторять платные запросы автоматически.

`write_file` создаёт или заменяет текстовый файл в существующей папке; shell,
Git-операции, создание каталогов, патчи, checkpoints/undo и MCP в этот цикл пока
не включены. Auto не следует считать полноценной средой программирования.

История записывается атомарно после шагов и управления, при потоковом тексте —
примерно раз в две секунды. При аварийном завершении последние секунды вывода
могут потеряться. После рестарта активный чат становится приостановленным;
автоматическое повторение инструментов не выполняется. Проекты, очередь,
план, текст и изображения сохраняются. Экспорт — JSON без API-ключей.
Показанное usage относится к последнему запросу, не к общей стоимости.
Компакт и автокомпакт описаны ниже: бюджет контекста там приблизительная оценка
(байты ≈ / 3), а не model-aware лимит провайдера.

## Какая модель отвечает

Модель и провайдер выбираются в панели «Модель» и входят в снимок настроек
каждого сообщения. Выбор видно в интерфейсе в трёх местах:

- блок «Контекст» под полем ввода — в заголовке («… · модель: провайдер ·
  Model ID») и первой строкой: куда уйдёт следующий запрос и от какой модели
  получен последний ответ;
- панель контекста справа — строка `Модель: …` рядом с шагом и usage;
- шапка каждого ответа ассистента — `провайдер · Model ID`, которым он получен,
  даже если модель в панели уже сменили.

Каждый ответ хранит собственные `provider`/`model`, поэтому смена модели посреди
разговора не переписывает старые: в блоке «Контекст» появляется пометка, что
панель «Модель» изменена. Это же видно в экспорте разговора — в `settings` и в
каждом сообщении. В режиме Swarm блок «Контекст» показывает модели участников и
синтезатора: отвечают они, а не модель сессии. Для локального `allpaka serve`
модель и занятость контекста печатает `allpaka status` (`/health`, `/stats`), а
сам веб-чат Studio работает через облачные или локальные API и GGUF не грузит.

## Swarm-режим

Swarm запускает не один диалог, а волну независимых агентов по одной задаче:
у каждого участника своя персона, свой провайдер и своя модель. Участники читают
подключённый контекст инструментами `list_files`/`read_file` и пишут отчёт, после
чего синтезатор сводит отчёты в один MASTER-ответ: сводка, топ подтверждённых
пунктов с указанием источника, следующие шаги, конфликты и неподтверждённое.

| Параметр | Контракт |
|---|---|
| Участники | 2–6; у каждого имя, роль, провайдер и Model ID, имена уникальны |
| Волны | 1–2. Во второй волне участник видит свой отчёт и выжимки чужих — как непроверенные данные |
| Ответов участнику | 1–8: лимит шагов чтения контекста на участника за волну |
| Синтез | отдельный провайдер/модель или «как у сессии»; критик-проход подключается отдельным флажком |
| Стоимость | `участники × волны + 1 (+1 критик)` запросов к провайдерам на один ход; интерфейс показывает число до отправки |
| Запись файлов | недоступна. `write_file`/`edit_file` не выдаются участникам, вызов отклоняется сервером, MCP-инструменты подключаются только в read-only виде |
| Отчёты | хранятся в самом assistant-сообщении и раскрываются по участнику; провайдеру не отправляются |
| Отмена | «Стоп» прерывает всю волну; отчёты, не успевшие завершиться, помечаются «отменено» |
| Steer | применяется на границе волны и в синтезе, а не посреди ответа участника |
| Частичный сбой | упавший участник помечается ошибкой и называется в итоге; если не ответил никто, ход завершается ошибкой — результат не выдумывается |
| Повтор участника | «Повторить участника» на карточке отчёта перезапускает только его и пересобирает MASTER из всех отчётов: один запрос участника + синтез (+ критик), `usage` показывается за этот повтор |

Честные ограничения: одновременно запускаются не более трёх участников (лимиты
провайдеров), отчёт каждого участника обрезается до ~6 КБ при передаче в синтез
(настраивается), окно контекста считается по модели самого участника, а не по
модели сессии. Автокомпакт перед swarm-ходом не запускается: историю можно сжать
вручную кнопкой «Компакт». Если синтезатор упёрся в лимит токенов, «Продолжить»
запускает новую волну по тому же запросу — это осознанный повтор, а не бесшовное
дописывание ответа. Swarm — не замена Auto: он исследует и объясняет, ничего не
меняя в проекте. Повтор участника доступен только для последнего Swarm-хода и
пока режим разговора — Swarm: перечитывать старый ход означало бы переписать его
историю. Из отчёта берутся провайдер и модель участника, а роль — из текущего
состава, поэтому после правки состава повтор прежнего имени получает общую роль.

## Рендер транскрипта

`web/app.js` опрашивает состояние сессии каждые 650 мс, и каждый опрос, в котором
что-то изменилось, перестраивал весь транскрипт. На 160 сообщениях с кодом это
65–708 мс на построение узлов и 82–1626 мс на весь `render` (в нём есть
принудительное чтение `scrollHeight`, то есть перерасчёт лэйаута). Теперь узлы
всех сообщений до первого изменившегося переиспользуются: те же цифры дают
~3 мс и ~9 мс.

Охота продолжалась на тех же 160 сообщениях и 844 КБ ответа и упёрлась в числа,
которые ничего не требуют: `fetch` вместе с сервером — ~2 мс (сервер собирает тело
за ~1 мс), `r.json()` — 3–5 мс, `render` без изменений — ~8 мс, с дописанным
последним сообщением — ~9,5 мс. Итого ~7 мс из 650 мс в простое и ~16 мс во время
генерации, то есть 1–2 % основного потока. Отклонены по этим числам, а не по вкусу:
`ETag`/304 на `GET /api/sessions/:id` (сняло бы ~6 мс раз в 650 мс, а риск — отдать
устаревший транскрипт там, где счётчик ревизий не обновляется), замена повторного
`JSON.stringify` в гарде (это 1 мс из 9) и мемуизация списка разговоров (3,6 мс раз
в 5 с). Замеряться надо осторожно: `structuredClone` внутри замеряемой области
превращает честные 9,5 мс в 79 мс.

Правило непригодности — префикс. Транскрипт дописывается в конец, а компакция,
ветвление и импорт меняют начало истории, поэтому кэш действует только до
первого отличающегося сообщения, и смена статуса хода (`running` печатается в
узле) или переключателя «Анализ» сбрасывает все узлы.

Автоматического гарда нет: у `app.js` нет тестовой обвязки. Проверка делалась в
живом браузере — прогон с кэшем и прогон с полным перестроением одного и того же
содержания дают побайтово одинаковый `#messages.innerHTML`.

## Проверки

```bash
cargo test -p allpaka-chat --offline
cargo build -p allpaka-cli --no-default-features --offline
python3 scripts/test-studio.py
node --check crates/allpaka-chat/web/app.js
```

Сквозной тест запускает собственный локальный mock API и Studio в временной
папке. Проверяет потоковый ответ, очередь, Steer, немедленную отмену, Stop/Resume,
запрет записи в Plan, разрешённую запись Auto, второй корень контекста, формат
изображения и восстановление истории/проектов. Swarm проверяется там же: две
волны участников в одном ходе, сводный MASTER, что отчёты участников не уходят
провайдеру, суммарный usage, ошибка одного участника, его повтор с пересборкой
итога, критик-проход, «Стоп» посреди волны и перенос отчётов через экспорт/импорт.
Платные запросы не выполняются.
Живые проверки семи облачных API требуют ключей и доступных моделей.

Обзор и дальнейшие приоритеты: [100 проектов](research/chat-2026-09-21/README.md).

## Ветки разговора

У завершённого ответа доступно «Продолжить в новой ветке». У обычного сообщения
пользователя — «Изменить в новой ветке» и «Повторить в новой ветке». Оригинал
сохраняется, ветка получает отдельный ID и ссылку на исходный разговор. Очередь,
план и ошибки не копируются. Незаконченный ответ или пакет инструментов нельзя
разрезать ветвлением. Изменение открывает черновик; повтор сразу отправляет
исходное сообщение с его изображениями. Несохранённый черновик не затирается.
Файлы проекта общие: ветвление истории не отменяет ранее выполненную запись.

Полный план расширения по каталогам: [матрица возможностей](research/chat-2026-09-21/capability-coverage.md).

## Отображение кода и diff

Блоки fenced code выводятся с сохранением отступов и кнопкой копирования.
Блоки `diff`/`patch` и текст unified diff показывают имена файлов, заголовки hunks,
старые/новые номера строк и количество добавлений/удалений. Цвета учитывают тему;
длинные строки прокручиваются горизонтально. Незакрытый блок показывается во время
стриминга. HTML внутри кода отображается как текст. Это просмотр патча, не его
применение и не подтверждение фактического изменения файлов.

Проверка парсера: `node scripts/test-studio-content.cjs`.

## Точечные изменения и фактический diff

`edit_file(path, old_text, new_text)` заменяет ровно одно совпадение непустого
`old_text`. Отсутствующий или неоднозначный фрагмент вызывает ошибку без записи.
Остальной текст сохраняется. Как и `write_file`, инструмент доступен только в Auto
с разрешением записи в чате и у папки. Размер редактируемого файла/результата —
до 128 KiB. Оба инструмента возвращают unified diff; результат инструмента
показывает его отдельно с номерами строк и подсветкой.

Diff описывает прочитанное состояние до записи и записанный результат. Это не
блокировка файла от параллельных внешних редакторов и не checkpoint/undo.
Контрактный тест применяет возвращённый патч через `git apply` к исходной копии
и сверяет байты с результатом, включая отсутствие завершающего перевода строки.

## Компакт и автокомпакт

Кнопка «Компакт» вызывает выбранную модель для резюме ранней истории без
инструментов. Оригинальные сообщения не удаляются и остаются в экспорте.
Последние два пользовательских хода с ответами/инструментами сохраняются целиком;
если более ранних ходов нет, сжатие не выполняется. Резюме можно прочитать
в панели «Краткий контекст». Ветки начинают с оригинального префикса истории.

Автокомпакт включён по умолчанию: перед запросом проверяется приблизительный
размер истории (UTF-8 байты / 3, плюс оценка для изображений и сообщений).
Порог по умолчанию 24000, настраивается в панели контекста и применяется при
следующей отправке/продолжении/ручном компакте. Это не точный токенизатор и не
автоматически полученный лимит модели. Системные инструкции и схемы инструментов
не входят в эту оценку; оставляйте для них и ответа запас. Два сохранённых хода
могут сами превышать порог.

Для резюме используются последовательные части до 24000 байт с предыдущим
резюме и лимитом выхода 2048 токенов. Это дополнительные API-запросы к выбранному
провайдеру. Старые изображения описываются именами, их пиксели остаются только
в полной истории. Оборванное/пустое/несокращающее резюме не применяется; ошибка
останавливает задачу с сохранением контекста. «Стоп» отменяет текущий компакт.
Резюме и граница сжатия сохраняются на диск; оригиналы не подменяются.

## OpenRouter

Подключение OpenRouter использует `https://openrouter.ai/api/v1` и
`OPENROUTER_API_KEY` либо ключ из «Подключений». Публичный каталог доступен без
ключа. После «Обновить список» выбор Model ID показывает контекст, лимит ответа,
входные модальности, поддержку tools и цены за миллион токенов, когда эти поля
возвращает API. Это информация каталога, не гарантия доступности endpoint.

Потоковые `reasoning_details` сохраняются без перестановки/изменения и возвращаются
только той же модели OpenRouter; перенос на другую модель/провайдера и replay
оборванного блока исключены. `reasoning` поддерживается как текстовый вариант.
Поле `usage.cost`, если присутствует, показывается для последнего запроса.
Настройки fallback/provider routing и суммарные бюджеты ещё не реализованы.

Источники: [API](https://openrouter.ai/docs/api/reference/overview),
[reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens),
[каталог](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties).
Проверено: публичный каталог и UI, локальные контрактные тесты. Платный запрос
OpenRouter с реальным ключом в этой проверке не выполнялся.

## Управление историей

Поиск проверяет заголовки и содержимое всех сообщений выбранного проекта и
раздела, без учёта регистра. Сжатые сообщения остаются доступны поиску. Разделы
«Чаты», «Архив» и «Корзина» независимы; физического удаления файлов нет.
В меню «Разговор» доступны переименование, архивирование, перемещение в корзину
и восстановление. Работающий разговор сначала нужно остановить. Состояние
раздела и заголовок переживают перезапуск. Архив и корзина не принимают новые
задания до восстановления; восстановление само не запускает очередь.

«Импорт разговора» принимает JSON, полученный кнопкой «Экспорт» Studio, до 9 MB
в интерфейсе (лимит API тела — 10 MB). Он создаёт новый ID в выбранном проекте,
проверяет роли и связанные пары tool calls/results. Импорт не переносит очередь,
разрешение записи, статус выполнения, ссылки ветвления и компакт-резюме: исходные
сообщения сохраняются полностью, выбран режим Chat. Ключ провайдера для самого
импорта не требуется. Другие форматы экспорта пока не поддерживаются.

## Постоянное хранение API-ключей

В «Подключениях» можно выбрать память процесса или системное хранилище и
сохранить уже введённый ключ кнопкой «Сохранить текущий ключ». На macOS
используется Keychain, на Windows — Credential Manager через keyring. На других
платформах эта сборка предлагает память/ENV; системный backend пока не реализован.

При запуске ENV имеет приоритет; иначе загружается сохранённая запись. UI
показывает источник ключа и ошибки хранилища. Секреты не возвращаются API и не
пишутся в историю; `credentials.state` содержит только ID провайдеров. Записи
системного хранилища привязаны к каноническому пути каталога истории: перенос
каталога требует повторной настройки ключей.

Замена ключа с отключённым системным хранением удаляет предыдущую сохранённую
запись. «Удалить ключ» очищает запись и память, но не меняет ENV: ключ из ENV
может вернуться после перезапуска. Ошибка системного хранилища не вызывает
сохранения в открытом виде. Удаление из Studio не отзывает ключ у провайдера.

Проверки macOS: native roundtrip с фиктивным ключом и полный API-сценарий
с перезапуском/удалением, без платных запросов и без пользовательских ключей.
Windows backend добавлен, но на Windows пока не проверен.

```sh
cargo test -p allpaka-chat --offline native_vault_roundtrip -- --ignored
ALLPAKA_TEST_NATIVE_VAULT=1 python3 scripts/test-studio.py
```

Предыдущий уже запущенный процесс без этой функции не умеет переносить свой
ключ в Keychain. После его первого обновления потребуется ввести ключ ещё раз;
последующие обновления смогут загружать сохранённую запись.
