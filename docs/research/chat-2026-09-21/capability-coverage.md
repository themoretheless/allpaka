# Покрытие возможностей двух каталогов

Запрос: возможности проектов из **обоих каталогов**, а не только подключение ключей.
Срез 2026-09-21: 65 записей Awesome BYOK Apps и 65 OpenRouter App Directory.
Это 130 записей каталогов, **не 130 уникальных приложений**: присутствуют повторы,
провайдеры, SDK, редакторы, шлюзы и специализированные сервисы.
Полный индекс ссылок: [catalog-inventory.json](catalog-inventory.json).
Предыдущий [обзор 100 проектов](README.md) — отдельная тематическая подборка.

Источники: [Awesome BYOK Apps](https://github.com/yatsyk/awesome-byok-apps),
[OpenRouter App Directory](https://github.com/OpenRouterTeam/awesome-openrouter).
Ниже — рабочая декомпозиция, а не заявление о полном паритете. Упоминание проекта
указывает источник направления для аудита. Детали каждого продукта ещё требуют
проверки в его документации; поэтому все записи исходного индекса имеют `audit: pending`.
Статус «частично» не засчитывается как завершение. Статусы относятся к коду, не к
обновлению запущенного экземпляра и не к проверке платного облачного API.

## Проверки текущей реализации

`cargo test -p allpaka-chat --offline`, `cargo clippy -p allpaka-chat --offline -- -D warnings`,
`node --check crates/allpaka-chat/web/app.js`, `python3 scripts/test-studio.py`.
Последний сценарий использует локальный mock, не подтверждает работу реальных облачных моделей.
Ветвление копирует только законченный префикс истории, исключает очередь/ошибки/план
и запрещено во время генерации. Повтор запускается отдельной отправкой в новой ветке.
Копирование истории **не откатывает файлы**, изменённые инструментами ранее.
