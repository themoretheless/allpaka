# 100 проектов для allpaka Studio

Дата проверки: 2026-09-21. Это отбор 100 релевантных проектов для проектирования продукта, а не мировой рейтинг по звёздам и не утверждение, что каждый проект поддерживает все шесть API. Порядковые номера служат для навигации. Первые десять приоритетов выделены в колонке идей.

Метод: найдены каталоги BYOK и OpenRouter, затем напрямую проверены 115 страниц GitHub. 112 ответили HTTP 200, три — 404. Убраны перенаправления-дубли и менее подходящие проекты. У каждого из 100 ниже есть проверенная публичная страница и исходное описание. Наличие функций подтверждается только на уровне README/описания проекта; запуск, лицензии каждой зависимости, качество, стоимость и безопасность всех 100 не аудировались. Архивный проект может быть полезен как исторический референс, но не как зависимость.

Первичные источники каждой строки — ссылки на соответствующие репозитории. Исходные URL, финальные URL после перенаправлений и описание сохранены в [projects-evidence.json](projects-evidence.json). Идеи для allpaka — наша оценка, а не обещание наличия конкретной функции у проекта.

## Основные выводы

1. Проект, чат и запущенная задача — разные сущности. У проекта есть инструкции и источники; у чата — сообщения; у задачи — режим, лимиты, очередь и состояние инструментов.
2. Контекст подключается явно: несколько папок/репозиториев, изображения и текстовые вложения. Для больших наборов нужны индекс, поиск, лимит контекста и видимость того, что отправлено провайдеру.
3. Plan ограничивается правами инструментов на сервере. Одного системного промпта «ничего не меняй» недостаточно.
4. Auto — ограниченный цикл model → tool → result → model. Нужны Stop, возобновление, лимиты шагов/стоимости и история действий.
5. Steer и Send now должны иметь разные контракты. Steer уточняет текущую задачу на границе шага. Send now отменяет текущую генерацию и ставит новое сообщение первым. Очередь остаётся видимой.
6. Совместимый API не означает одинаковые возможности: изображения, reasoning, tool calls, token limits и signatures зависят от модели.
7. Не копировать сто продуктов целиком. Важнее сквозной контракт состояния, на который добавляются MCP, RAG, shell, git, артефакты и фоновые задачи.
