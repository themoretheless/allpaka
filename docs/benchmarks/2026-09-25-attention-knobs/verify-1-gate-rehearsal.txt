Rehearsal 1 - `drive.py --check` (writes nothing, exits 0)
----------------------------------------------------------

    $ sha256sum drive.py
    3b4dc07eaf40d7d47c5b97f73bd526784d513e42d29257efe822c6b06511d58c  drive.py

    $ python3 drive.py --check
    binary /Users/themoretheless/Documents/Sources/allpaka/docs/benchmarks/2026-09-26-glm-mv-id-rerun/series-1/allpaka
      sha256 7b8ec67aa72c42662ba4608fa1629c139c759c6ce7bacdd6c6aa6fbcc46fe2fe
      expects 7b8ec67aa72c42662ba4608fa1629c139c759c6ce7bacdd6c6aa6fbcc46fe2fe -> ok
    load 5.33 against ceiling 5.0; settle 3 samples 30s apart; cap 40 min
      builders:      none
      other bench:   none
      indexer work:  none (class is resident and idle)
    rc=0

Read this the right way round: the three class verdicts are all "none" while the machine
carried load 5.33, so the guard was NOT clearing a quiet machine - it was clearing a busy
one whose busyness belongs to none of the three vetoed classes (the load at that minute
was the MV_ID rerun's own calibration processes plus ordinary desktop work, and the
rerun's driver is a `Python .../drive-mv-id.py` process, which this driver does not veto
by name - the serialization is done by the chained watcher, rehearsal 3, not by
`others_busy()`). `--check` prints the load and does not gate on it: it exists to be run
before a launch, and its only contract is that it starts no process and creates no
directory. Confirmed after the run: `ls series-1` -> "No such file or directory", and the
directory listing of `2026-09-25-attention-knobs/` holds only the driver, analyzer,
preregistration, this artifact, the watcher script and the watcher log.

Two things that gate buys and one it does not:
- The pinned binary is the rerun's build (`7b8ec67a...`), not `target/release/allpaka`,
  which at rehearsal time was whatever the other session's `cargo test --no-run` had last
  produced. A sha mismatch is a `SystemExit` before the quiet gate, not a warning.
- `builders: none` is an existence check (`pgrep -xl cargo,rustc,llama-bench`), so a live
  compile is what would have shown here; there was none at this sample.
- `other bench: none` was true at this instant because the rerun's bench processes fit
  between the sampler's windows; it is not a guarantee, and rehearsal 3 is the layer that
  does not depend on catching them.
