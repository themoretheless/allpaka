# Qwen3-30B-A3B Q4_K_M on Apple M4 Max

Measured on 2026-09-02 with the same
`models/qwen3-30b-a3b-Q4_K_M.gguf` file and full Metal execution.

| Workload | llama.cpp | allpaka | allpaka / llama.cpp |
| --- | ---: | ---: | ---: |
| `pp480` prefill | 988.15 tok/s | 1424.16 tok/s | **1.44x** |
| `tg32` decode | 69.45 tok/s | 121.48 tok/s | **1.75x** |

The target was at least `1.10x`; both measured workloads clear it. The earlier
`14.7 tok/s` decode and `13.4 tok/s` prefill figures describe the broken
fallback path and are not representative of the current engine.

## Method

allpaka was run five times with an explicit profile and a fail-closed GPU
benchmark:

```sh
ALLPAKA_PROFILE=max-performance \
ALLPAKA_BENCH_PP=480 \
ALLPAKA_BENCH_REPORT=/tmp/allpaka-final-bench-N.json \
target/release/allpaka bench \
  --engine models/qwen3-30b-a3b-Q4_K_M.gguf
```

The table uses the median of the five independent allpaka runs. The observed
ranges were `1418.09..1434.65 tok/s` for prefill and
`75.29..128.18 tok/s` for decode. The low decode outlier was retained rather
than discarded. Across all runs, the decode path recorded `160/160` GPU fast
path successes and zero declines.

llama.cpp was Homebrew build `10621`, commit `c1d0e7a00`, and reported an
Apple M4 Max with Metal, residency sets, shared buffers, and all 99 requested
GPU layers:

```sh
/opt/homebrew/bin/llama-bench \
  -m models/qwen3-30b-a3b-Q4_K_M.gguf \
  -p 480 -n 32 -r 5 -ngl 99 -o json
```

llama.cpp reports the arithmetic mean of its five in-process repetitions:
`988.15 +/- 44.75 tok/s` for prefill and `69.45 +/- 5.85 tok/s` for decode.
The tools therefore do not have identical process-lifetime statistics; the raw
commands and ranges are included so the comparison can be repeated.

As a context control, `llama-bench -pg 480,32` reported
`615.54 tok/s` for the combined prompt-plus-generation workload. It is not used
in the table because that aggregate does not expose a separate post-prefill
decode rate.

## Regression gate

After embedding the source revision into report metadata, a final candidate on
commit `6c8e6744be6b` produced `1433.05 tok/s` prefill and `126.44 tok/s`
decode. Against the selected baseline with a 20 percent tolerance, the report
gate passed at `+1.06%` and `+9.43%`, with `32/32` GPU successes and zero
declines.
