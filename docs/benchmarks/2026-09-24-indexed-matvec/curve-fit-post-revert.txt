# Curve fit on the reverted (unparameterised) q3_k tree - regenerated 2026-09-24

The README cited a file with this name for the claim that reverting the `q3_k`
NR0 parameterisation put its per-block cost `B` back to 463-464 against
`q4_k`'s 293. No such file existed (and `.gitignore` has `*.log`, so the name it
was cited under could not have been tracked anyway). This is that measurement
redone on the current tree, which carries the same revert.

Regime: one process, six formats, nb = 4/6/8/12/16 (q8_0: 32..128), 12 streamed
sets, feed=32, load average ~10-14 with another agent session building. Under
that load the meter itself is degraded - `q4_k`'s `B` reads 369 here against 293
in the quiet series - so the ABSOLUTE ps values below are not comparable to the
463/293 pair the old sentence quoted, and the two are not the same quantity:

    ratio to q4_k's B    this run      the quiet series
    q3_k                 730 / 369 = 1.98   463 / 293 = 1.58
    q5_k                 605 / 369 = 1.64   (NR0=4 shipped: 1.54 at its own shape)
    q2_k at nb=8         270 / 369 = 0.73

`A` (per-row cost) stays ~0 for every format except q2_k (1.8 ns/row), which is
the result that section was making: there is nothing to recover per row, and
`q3_k`'s deficit is per block. Note that the single-shape ratio measured the same
day at `[4096,1536]` x8 was 1.76 for q3_k against 1.32 for its no-arithmetic
probe - a fit extrapolated to nb->0 and a ratio measured at nb=6 are different
numbers, and this file's 1.98 should not be quoted as if it were the 1.76.

Reproduce: `cargo test -p allpaka-backend --test gpu_ffnbench -- --ignored
--nocapture --test-threads=1 indexed_matvec_curve`
