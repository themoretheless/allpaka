# q3_k run-locality probes: matvec_q3_k_ic / _icw against their twins

Shape `[4096,1536]` x8 indexed, 12 rotating expert sets, feed=32, one process
per arm, `q5_shape_ratio_against_q4`. Five reps x six arms, arm order rotated by
two slots per rep so position cannot be the experiment. Kept only runs whose own
controls are in band (q5_k 1.72-1.84, q6_k 1.30-1.53 against the in-run q4_k
meter); 24 of 30 kept, and the per-arm spread after that is +-0.01-0.026.

Each arm differs from its twin in exactly ONE property:

| arm | kernel | vs twin | weight loads per block-row |
| --- | --- | --- | --- |
| (incumbent) | matvec_q3_k_mv | - | 32 ushort, real arithmetic |
| nomath | matvec_q3_k_nm | - | 32 ushort, arithmetic removed |
| nomath_word | matvec_q3_k_nw | nomath | 16 uint on a 112-byte padded block |
| nomath_norowstep | matvec_q3_k_ns | nomath | 16 ushort (row 1 reuses row 0's) |
| contig | matvec_q3_k_ic | nomath | 32 ushort from ONE 32-byte run per lane |
| contig_word | matvec_q3_k_icw | nomath_word | 16 uint from ONE 32-byte run per lane |

## Result (mean ratio to the in-run q4_k meter, in-band runs only)

| arm | n | mean | sd | range | vs incumbent |
| --- | --- | --- | --- | --- | --- |
| incumbent | 4 | 1.808 | 0.070 | 1.739-1.906 | - |
| nomath | 4 | 1.383 | 0.010 | 1.372-1.396 | -22.9% |
| nomath_word | 4 | 1.319 | 0.010 | 1.306-1.329 | -26.4% |
| nomath_norowstep | 4 | 1.198 | 0.056 | 1.118-1.243 | -33.2% |
| contig | 3 | 1.410 | 0.016 | 1.395-1.426 | -21.3% |
| contig_word | 4 | 1.372 | 0.024 | 1.337-1.389 | -23.5% |

Pairwise, the two locality arms are slower than their twins: contig vs nomath
1.410 against 1.383 (+2.0%), contig_word vs nomath_word 1.372 against 1.319
(+4.0%). Both margins exceed the within-arm spread. Load width still buys what
correction 6 estimated, now resolved: nomath -> nomath_word is -4.6%.

## What this closes

The interleaved-plane repack was the last `q3_k` layout hypothesis: put each
16-quant group's mask bytes next to its quants so a lane's weight loads issue
from one run. It costs ~29% more weight bytes per block (the one-bit plane has
to be duplicated across the sub-blocks that share it) and cannot share the
model's zero-copy mmap, so it needed a measured gain to be argued at all.
Measured directly, contiguity at fixed count and width is worth -2 to -4% - it
goes the WRONG way, so there is no gain for the memory cost to pay against, and
the 26 GiB question never has to be asked. Kill condition was "ratio must fall
below ~1.20"; contig came in at 1.41.

What is left on q3_k is load COUNT, and nomath_norowstep shows where it goes:
halving the weight loads per block (-33% vs incumbent, 1.198) works only because
the probe lets row 1 reuse row 0's bytes, which real q3_k rows cannot do - they
are different output rows, i.e. different weights. A real kernel cannot reach
1.198 without changing the format's row ownership.
