# Управление worktree

Скрипт `scripts/git-worktree-manager.sh` (в составе плагина — `bin/git-worktree-manager.sh`,
рядом обязательная `bin/scripts-common.sh`). Работает поверх настоящего `git worktree`,
никакой изоляции не требует.

## Использование

```sh
scripts/git-worktree-manager.sh add feature-x .qoder-worktrees/feature-x
scripts/git-worktree-manager.sh add hotfix ./wt/hotfix --detach
scripts/git-worktree-manager.sh list
scripts/git-worktree-manager.sh list --verbose
scripts/git-worktree-manager.sh list --json
scripts/git-worktree-manager.sh remove .qoder-worktrees/feature-x
scripts/git-worktree-manager.sh prune --dry-run
scripts/git-worktree-manager.sh report
```

Команды:

- `add <ветка> <путь> [--detach]` — создаёт дерево; ветку заведёт, если её нет.
  Если ветку уже держит другой worktree — отказ (код 1) с подсказкой `--detach`.
  Путь занят — тоже отказ, ничего не перезаписывается.
- `list [--json|--verbose]` — путь, короткий SHA, ветка, флаг занятого основного
  дерева, отметка `*` у дерева с незакоммиченными изменениями.
- `remove <путь|ветка> [--force]` — только `git worktree remove`. Ветку не трогает:
  локальная ветка остаётся и её удаляют руками. На незакоммиченных изменениях
  отказывает, пока не сказан `--force`. Основной worktree не удаляется.
- `prune [--dry-run]` — убирает записи о worktree, чьих каталогов уже нет.
- `report [--path ГЛОБ]` — сводка по незакоммиченному в каждом дереве.

Коды выхода: `0` — успешно, `1` — отказ по безопасности (грязное дерево, занято,
основной worktree), `2` — неверные аргументы.

## Что важно знать про add

`git worktree add` не позволяет занять одну ветку двумя деревьями. Скрипт проверяет это
заранее по выводу `git worktree list --porcelain` и объясняет отказ, вместо того чтобы
показывать сырой `fatal: already checked out`. Для чтения чужой ветки в параллельном
дереве просите `--detach`.

## Почему remove не удаляет ветку

Удаление дерева и удаление ветки — разные решения: первое почти безопасно, второе
теряет коммиты. Скрипт делает только первое и печатает, какая ветка осталась.
Удаление ветки — отдельная явная команда пользователя (`git branch -D`), и перед ним
стоит посмотреть, есть ли unpublished commits.

## Грязное дерево

Перед `remove` показать состояние:

```sh
git -C <путь> status --short
```

`--force` выбрасывает незакоммиченную работу безвозвратно (её не вернёт `git stash`
и не покажет `git reflog`). Без явной просьбы его не использовать.

## Пути

Скрипт сравнивает пути физически (`pwd -P`), потому что на macOS `/tmp` — симлинк на
`/private/tmp`, и логический путь не совпадает с тем, что отдаёт `git worktree list`.
Отсюда же рекомендация не держать деревья в `/tmp` дольше сессии.

## Окружение

Требования минимальны: `git` в PATH и запуск внутри git-репозитория (для `list`,
`remove`, `prune`, `report` — из любого worktree этого же репозитория). `jq` нужен для
`--json`. Ни MCP, ни контейнера: обычный доступ к командной строке.
